# Security

## Threat model

task-eta runs on every prompt, as a Claude Code hook, with your user's permissions. It handles:

| Input | Risk |
|---|---|
| Claude Code transcripts (`~/.claude/projects/*/*.jsonl`) | They contain everything you and Claude wrote, including text pasted from the web and keys you may have pasted. Personal data could leak if it were copied anywhere else; hostile text could try to steer Claude when it is shown back as a "similar past request"; odd or huge records could stop or slow the parser |
| The JSON Claude Code passes to the hooks on stdin | Malformed or unexpected input must never break a prompt or write outside the data folder |
| Model and effort names | They come from the transcript or the desktop app, and through a gateway or proxy from a third-party server: they must not carry text into Claude's context |
| `~/.claude/settings.json`, `~/.claude/CLAUDE.md`, `~/.claude/skills/task-eta` | The installer edits files that control Claude Code; a bad edit could disable your other hooks, lose your settings or replace another skill |
| The widget's live files and the Claude desktop app's session files | Read by a long-running app; a path inside them must not make it open or run anything |
| Other user accounts on the same Mac | The index holds prompt snippets: it must not be readable by them |

Assets protected: your transcripts and prompts (they never leave the machine), secrets you pasted into prompts, your Claude Code configuration, and the file system outside `~/.claude/task-eta`.

## Mitigations implemented

| Mitigation | Where |
|---|---|
| No network code: Python standard library only (no `urllib`, `socket`, `http`), the Swift app uses no networking API. Nothing is downloaded at install; the widget is compiled from the source in this repository | `task_eta.py`, `install.py`, `widget/Sources` |
| Nothing is installed without a yes: the first question is whether to install at all, and any question left unanswered (no terminal, no command-line answer) counts as no. Reading past sessions is a separate yes; with a no, the start date goes in `config.json`, and while it is there tasks that started before it are never indexed and transcripts not written since are never opened. A `config.json` that cannot be read fails closed (its own date counts); deleting it lifts the choice | `install.py` (`Ctx.ask`, `install`), `task_eta.py` (`history_since`, `update`) |
| Private files: both scripts run with umask 077, every file is created with mode 0600 and every folder with 0700. The installer tightens what older versions left readable (everything in the default data folder; in a folder set through `TASK_ETA_DIR`, only the files task-eta wrote), and `--check` reports anything still readable by others | `task_eta.py` (`main`, `private_dir`, `write_json`, `write_live`), `install.py` (`step_private`, `check`) |
| Data minimisation: the index keeps the first 300 characters of each prompt, the first 400 of each subagent brief (written by Claude, used to estimate subagents), durations, model, effort, tool names and tool-use ids, file extensions, the name of the working folder, the transcript path and the session id. Claude's replies are not kept (older indexes are cleaned of them) | `task_eta.py` (`finish`, `parse_subagent`, `scrub`) |
| Secrets are masked before anything is stored or shown, on the whole prompt before it is cut (a key cut in half would no longer look like one): keys by prefix (`sk-`, `sk-ant-`, `sk-proj-`, `xai-`, `ghp_`/`gho_`/`ghu_`/`ghs_`/`ghr_`, `github_pat_`, `glpat-`, `hf_`, `AKIA`/`ASIA`, `AIza`, `xox*-`, `pk_`, `sk_live_`, `rk_live_`, `stk_`, `proapi_`, `npm_`), PEM blocks, JWTs, SendGrid keys, keys in URLs (any path or query segment of 20+ letters and digits mixed, so RPC keys of any provider) and webhook URLs, `user:password@host` (also with no user, `redis://:password@host`), `curl -u user:password`, `Bearer` tokens, base64 keys with `+` or `/` (cloud storage, AWS secret keys), values after a secret-sounding name, also with a prefix or in camelCase (`password: …`, `DB_PASSWORD=…`, `PGPASSWORD=…`, `SMTP_PASS=…`, `dbPassword=…`, `clientSecret: …`, `--token …`, `AccountKey=…`, `"api_key": "…"`), and any run of 24+ letters and digits mixed. Index, live files, hook block, background job names and widget markers all get `[secret]`. A new pattern version scrubs the whole stored history and its daily copy once, transcripts gone or not | `task_eta.py` (`SECRET_RE`, `KEYWORD_RE`, `URL_RE`, `redact`, `ensure_scrubbed`, `save_index`) |
| Past prompts shown to Claude: none in the hook block or in `estimate`, which list similar past requests by kind, time and tool calls only (since 2026-10-28); in `report` and `status`, only from the same project as the current session (none when the project is unknown; other projects' tasks appear without their prompts); normalised (NFKC, so fullwidth look-alikes become plain characters), with control, format and surrogate characters (bidi overrides and ANSI escapes included), quotes and their look-alikes, square and angle brackets and ⏱ ⏲ removed, so a snippet cannot pass for the block's own text or for a tag such as `<system-reminder>`; cut to at most 200 characters; prompts of automated `claude -p` runs are never shown | `task_eta.py` (`short`, `shown_prompt`, `estimate_block`, `project_of`) |
| Model and effort are checked before they are stored or shown: a model name must look like one (lowercase letters, digits and `._:@/-`, up to 48 characters and 8 separators, with a digit), an effort must be one of low, medium, high, xhigh, max; anything else is unknown (`?`) | `task_eta.py` (`valid_model`, `valid_effort`, `model_tag`) |
| One odd record cannot stop the indexing: every field the parser uses is coerced to the type it expects (a string or nothing, an object, a list of objects) when the line is read; a subagent transcript that still fails is skipped and logged, and the session's own tasks count; a transcript that still fails is skipped and logged in `errors.log`, and the others are indexed; stored tasks are checked the same way when the index is read | `task_eta.py` (`load_record`, `attach_subagents`, `parse_transcript`, `update`, `read_index`, `clean_task`) |
| Hostile transcript text cannot slow the hooks down: ⏱ lines are cut to 300 characters and parsed with patterns that have no adjacent open-ended repeats; every other pattern has bounded or linear repeats (tags, secrets, the "asks the user" check, which trims with `rstrip`); estimates and ranges above a week are ignored; wrapped blocks (reminders) are removed in linear time even when their closing tag is missing; messages are looked at up to 100,000 characters; transcript lines are read with a size limit, and a line over 32 MB is skipped piece by piece instead of loaded; a lone surrogate (half an emoji) is replaced; lines nested too deep for the JSON parser are skipped; timestamps outside 2000 to 2100 are ignored. Tests time each of these on adversarial input | `task_eta.py` (`EST_RE`, `DROP_OPEN`, `drop_tags`, `asks_user`, `jsonl_lines`, `load_record`, `parse_ts`), `tests/test_hardening.py`, `tests/test_review.py` |
| Only plain files are read: a transcript, subagent transcript, subagent `.meta.json`, live file or desktop-app session file that is a FIFO, a device or a folder is skipped, in the hooks and in the widget. The calibration, and a full re-parse after a parser change, run as their own background processes, so the Stop hook stays quick on a long history | `task_eta.py` (`regular_file`, `calibrate_in_background`, `update_in_background`), `widget/Sources/TaskStore.swift` (`isRegularFile`) |
| Session ids from hook input are reduced to ASCII `[A-Za-z0-9_.-]` before they become file names, so they cannot leave the live folder; the PostToolUse shell hook exits unless the id is made only of ASCII letters, digits, `_` and `-` (spelled out, not a locale-dependent range) | `task_eta.py` (`live_path`, `input_path`), `install.py` (`our_hooks`) |
| Live-file cleanup, `--purge` and the installer's tightening of file modes touch only files task-eta wrote, checked by their content: an index needs its version, tasks and files; labels need 16-hex keys; the start-date file holds only a number; logs start with task-eta's own line; the lock and "no live files" markers hold task-eta's text (an empty one, from an older version, counts only in the default folder); a waiting-for-you marker needs its exact keys and a known kind. Temporary files count only with task-eta's own prefix (`.tasketa-` in the live folder) or name, and moved-aside index copies are removed only from the default folder. A folder chosen through `TASK_ETA_DIR` or `TASK_ETA_LIVE_DIR` is never removed. A `config.json` or `install.json` of the same name that task-eta did not write is never deleted or replaced: the installer stops before changing anything. Empty values of these variables count as unset | `task_eta.py` (`live_prune`, `is_live_file`, `is_input_file`, `is_tmp_file`), `install.py` (`DATA_FILES`, `MARKED_FILES`, `data_file_is_ours`, `purge`, `save_state`, `install`) |
| Hooks never fail a prompt: input that is not a JSON object, is nested too deep or has fields of the wrong type counts as empty; errors are logged in `errors.log` (private) and never printed; every hook command ends with `\|\| true` | `task_eta.py` (`read_hook_input`, `quietly`, `log_error`, `main`), `install.py` |
| Parallel sessions do not lose each other's tasks: transcripts are parsed first, then the index is loaded, merged and saved under an exclusive lock. Writes are atomic (temporary file, then rename) for the index, its daily copy, the calibration, the labels, live files, `settings.json` and `CLAUDE.md`; temporary files and logs are opened without following links (`O_NOFOLLOW`, and `O_EXCL` for new files), so a link planted in a shared folder is removed, never written through. An index this version cannot read is moved aside (`index.json.unreadable-<time>`), never overwritten, and the daily copy stands in, so tasks whose transcripts are gone are not lost | `task_eta.py` (`index_lock`, `update`, `cmd_hook_stop`, `load_index`, `save_index`), `install.py` (`write_atomic`) |
| `elapsed` and `eta` report only the session named by `CLAUDE_CODE_SESSION_ID`; without it they print nothing | `task_eta.py` (`current_task`) |
| Installer: checks everything before writing anything (valid JSON, expected shapes, UTF-8, writable files and folders, one clean pair of CLAUDE.md markers, a `config.json` and `install.json` of its own) and stops with nothing changed otherwise; reads `settings.json` and `CLAUDE.md` again right before writing them, so changes Claude Code made while the questions were open are kept, and if one of them turned invalid meanwhile it stops and says which changes were already made; points out backups an earlier version left next to your files; backs up every file into `~/.claude/task-eta/backups` (0700) under names that are never reused, keeping the last 10 of each file and always the one uninstall restores from; follows a `settings.json` or `CLAUDE.md` that is a link and changes its target instead of replacing the link; finds its own hooks only by a tag it writes (`# task-eta-hook`) or by the exact shape of older task-eta hooks, so no other hook is touched; shell-quotes every path in hook commands and in the rule | `install.py` |
| Uninstall puts `settings.json` and `CLAUDE.md` back byte for byte when nothing else changed them since the install (it keeps the hash of what it wrote and the copy made before it first touched them); otherwise it removes only what task-eta added and keeps hook events that were empty lists before | `install.py` (`remember`, `restore`, `strip_ours`, `uninstall`) |
| The skill link: a real `~/.claude/skills/task-eta` folder, or a link to anything that is not task-eta, is left alone (the skill is then not linked). A link to another copy of task-eta is pointed here only after saying so before the questions, and `--uninstall` points it back | `install.py` (`skill_link_plan`, `step_skill_link`, `uninstall`) |
| Installer and the widget app: an existing `~/Applications/TaskETA.app` is replaced or deleted only if it is a real folder (not a link) with this widget's bundle id; the running widget is closed by the exact path of that app's executable, never by name (`pkill`), so no other program called TaskETA is touched; a read-only `CLAUDE.md` is left as it is on uninstall | `install.py` (`app_is_ours`, `app_pids`, `quit_app`), `widget/build.sh` |
| Widget: every number read from a file is checked (finite, within a plausible range, a marker time never in the future) before any conversion, so broken or hostile files cannot crash it or make its clock negative; it reads Claude's ⏱ line at most 512 KB per refresh and stops 8 MB in; it shows the live folder in the Finder with `activateFileViewerSelecting`, never `open`, so a planted path cannot launch an app; text from files is rendered verbatim (`Text(String)`); "Hide prompts and titles" shows only folder names, for screen sharing; its lock file is private; it requests no entitlements and runs nothing. `TaskETA --selftest` checks these parsers inside the app's own code | `widget/Sources/TaskStore.swift` (`sanitized`, `safeInt`, `parseDeclaredLine`), `widget/Sources/Prefs.swift`, `widget/Sources/main.swift` (`SelfTest`) |
| Published files are checked by a test for email addresses, home-folder paths (also as Claude Code encodes them in folder names), session ids, secret-like strings, PNG text chunks and data files; `.gitignore` excludes data files, exports, widget debug output and Claude Code's per-project folder | `tests/test_no_private_data.py`, `.gitignore` |
| CI actions are pinned by commit SHA, run with read-only permissions and `persist-credentials: false`; Dependabot keeps the pinned actions up to date | `.github/workflows/ci.yml`, `.github/dependabot.yml` |

Tests with hostile or broken input: `tests/test_hardening.py` (one test per finding of the pre-release review), `tests/test_review.py` (one test per finding of the post-release review of 2026-10-20: file modes, odd records, model and effort carrying text, foreign skill links, snippets from other projects and pasted keys, slow patterns, foreign files in a chosen data folder, byte-for-byte uninstall, control characters in `status`, huge lines, odd hook input, settings changed during the questions, backups, closing the widget, parallel Stop hooks, `elapsed` without a session id, the widget's own checks), `tests/test_review2.py` (one test per finding of the independent review of this version: quadratic masking, an odd subagent record, more secret formats, keys cut before masking, a foreign undo file, look-alike files, a broken start date, other projects in `report` and `status`, sentence-like model names, left-behind copies, a stop midway, planted links), `tests/test_install.py` and `tests/test_v2.py`.

## Residual risks

- **Snippets of your past prompts reach the model when you ask for them.** The hook block no longer quotes past prompts (since 2026-10-28), but `report` and `status`, which the skill runs when you ask, show snippets of the same project's prompts to Claude. If a past prompt contained pasted hostile text, a piece of it could appear there.
- **Secret masking is pattern-based.** It catches the formats listed above, not every secret: a short password typed with no name before it (`mysql -pS3cret`, "my password is hunter", a passphrase in plain words), a key of an unknown format under 24 characters, or a secret split by spaces stays in the 300-character snippet in the index, and its start can show in `report`, `status` and the widget. Do not rely on it as your only protection: rotate any key you pasted into a prompt.
- **The index holds prompt snippets in plain text** in `~/.claude/task-eta/index.json`, private to your user (0600): anything that runs as your user can read it, as it can read the transcripts it comes from. `install.py --uninstall --purge` deletes it, with its daily copy and any copies set aside; the backups of `settings.json` and `CLAUDE.md` in `~/.claude/task-eta/backups` are kept, because they are copies of your own files.
- **"Start from today" lives in one file.** If `~/.claude/task-eta/config.json` is deleted while the hooks stay installed, the next re-parse reads the older sessions too.
- **`TASK_ETA_DIR` and `TASK_ETA_LIVE_DIR` should name private folders.** Writes there never follow links, but a folder others can write to is still a shared folder.
- **The transcript format is not a public API.** A Claude Code update could make the parser miss tasks. Failures are logged in `errors.log`, and `report` and `install.py --check` point to it, but the hooks themselves stay silent.
- **The widget is signed ad hoc**, not notarized: it is built on your Mac from this source, so Gatekeeper does not quarantine it, but there is no Apple signature to check.
- **Hooks run with the Python that ran the installer.** If that Python is removed or replaced, the hooks stop (quietly) until you run `install.py` again.
- **`TASK_ETA_DEBUG`** (a debugging aid, undocumented elsewhere) writes the hook's model and effort inputs and the matching environment variables to `debug-hook.json` in the data folder, private to your user.

## Reporting a vulnerability

Please use GitHub's private vulnerability reporting: the **Security** tab of this repository, then **Report a vulnerability**. Do not open a public issue for security problems. Include the input that triggers the problem and what you expected to happen.
